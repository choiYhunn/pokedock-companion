# M6 실물 착수 가이드 — 주문부터 G1·G2까지 순서대로

이 문서만 따라 하면 됩니다. 세부 측정표는 `G1_G2_INSPECTION_KO.md`와 `G1_G2_RECORD_TEMPLATE.csv`에 있습니다.

**장비 구분**
- **[기본]**: 멀티미터, 캘리퍼, 틈새 게이지, 인두만 있으면 됩니다.
- **[권장]**: 저가 USB-C 전류계(1–2만 원대)가 있으면 편합니다.
- **[전문]**: 오실로스코프나 열화상 카메라가 필요합니다. 이번 G1/G2에는 **[전문]** 항목이 없습니다. 소리 크기는 귀로 판정하고, 발열은 손 접촉과 멀티미터 온도 프로브(있으면)로 확인합니다.

## 0. 지금 주문 (`procurement/BOM_M6.csv`의 tier A)

1. **Waveshare 공식몰**: ESP32-S3-Touch-AMOLED-1.43 **케이스 없음 SKU 30106**. 예비 1개를 포함해 2개를 권장합니다.
   - 주문 화면에서 SKU 30106인지, **"-B"나 "C"가 아닌지** 확인합니다.
2. **Digi-Key Korea 한 번에 주문**(₩60,000 미만이면 배송비 ₩20,000):
   - Adafruit 4090 ×2 (1528-2873-ND)
   - Bourns MF-R075 ×2
   - Soberton WT-1205 ×2 (433-1028-ND)
   - AOS AO3400A ×3
   - onsemi 1N4148 ×3
   - 100 Ω ×3
3. **국내 소모품**: 100 kΩ, SOT-23→DIP 변환기판, 만능기판, 전선, 수축튜브, 나사·인서트, 실리콘 발, 폼테이프, USB-C 먼지마개.
4. **공구**: 없는 것만 구매합니다(T1, T2).

> 1.27 mm 2×7 소켓(B1)과 출력물(C1, C2)은 **아직 주문하지 않습니다.**

## 1. 보드 도착 당일 — 사진·치수 (약 30분) [기본]

1. 보드를 흰 종이 위에 놓고 G1-P1–P7 사진을 찍습니다(`G1_G2_INSPECTION_KO.md`의 G1-A 표).
2. 캘리퍼로 G1-M1–M7을 측정하고 기록 양식에 적습니다.

**합격하지 못하면 수정할 곳**

| 불합격 항목 | 수정 파일 · 파라미터 | 그다음 |
|---|---|---|
| G1-M1 유리 외경 | `cad/m6_params.py` `GLASS_R`(= 실측/2). `POCKET_R`는 자동으로 +0.50 | `bash tests/run_all.sh` 재통과 |
| G1-M2 유리→스탠드오프 높이 | `GLASS_TO_STANDOFF` | 같음 |
| G1-M3 헤더 핀 높이 | `SOCKET_Y` | 같음 |
| G1-M4 스탠드오프 간격 | `STANDOFFS_XZ` (±15.75, ±11.60) | 같음 |
| G1-M7 4090 치수 | `USB_PCB`, `USB_HOLES`, `USB_CONN`, `USB_CONN_PROTRUDE` | 같음 |
| G1-M6 J1–버튼 틈 < 0.25 mm | 소켓 대신 단일 핀 하우징 또는 납땜(BOM B1 비고) | — |

## 2. 공장 펌웨어 확인과 백업 (약 15분) [기본]

1. 보드 자체 USB-C → PC(USB 전류계 연결 권장). 출고 펌웨어 화면이 나오는지 확인합니다.
2. PowerShell에서 장치 관리자의 COM 번호를 확인한 뒤, 출고 이미지를 **먼저 백업**합니다:
   ```
   cd v16\masterball-m6\tools
   .\flash_windows.ps1 -Port COM5 -Backup
   ```
3. 필요하면 Waveshare 공식 데모 패키지(`ESP32-S3-AMOLED-1.43-Demo-V3.zip`)의 `Firmware\ESP32-S3-Touch-AMOLED-1.43-factory.bin`을 플래시합니다:
   ```
   .\flash_windows.ps1 -Port COM5 -Image <경로>\ESP32-S3-Touch-AMOLED-1.43-factory.bin
   ```
4. 측정:
   - G1-E1: 전류 < 250 mA
   - G1-E2: J1-4 ↔ J1-6이 4.75–5.25 V, J3-1 ↔ J3-7이 3.25–3.35 V
   - G1-E3: J2 전압(기록만)

## 3. M6 펌웨어 빌드·플래시 (약 20분, 처음엔 툴 설치에 40분) [기본]

1. WSL Ubuntu에서 처음 한 번만 툴을 설치합니다:
   ```
   bash v16/masterball-m6/tools/idf_setup_wsl.sh
   ```
2. 빌드합니다(결과: `firmware/out/pokedock_m6_merged.bin`):
   ```
   bash v16/masterball-m6/tools/idf_build_wsl.sh
   ```
3. Windows에서 플래시하고 로그를 봅니다:
   ```
   .\flash_windows.ps1 -Port COM5 -Image ..\firmware\out\pokedock_m6_merged.bin
   .\flash_windows.ps1 -Port COM5 -Monitor
   ```
4. **G1-E4 합격 기준**: 로그에 다음 세 가지가 모두 있어야 합니다.
   - `panel RDID=0x86 -> SH8601` 또는 `0xff -> CO5300`
   - `touch: chip_id=0x.. vendor=0x11`
   - `RTC NOT set`

## 4. 화면·터치 방향 (약 10분) [기본]

- **G1-E5**: USB-C가 아래를 보게 들었을 때 시계가 바로 서 있어야 합니다.
  - 뒤집혀 있으면 `bash tools/idf_build_wsl.sh rotate180`으로 다시 빌드해 플래시합니다(`CONFIG_PD_SCREEN_ROTATION_180`). 터치 좌표도 함께 돌아갑니다.
- **G1-E6**: 중앙과 상하좌우 5점을 탭합니다. 로그 좌표가 목표의 ±15 px 이내면 합격입니다.
  - 불합격(축이 바뀐 경우)이면 `firmware/main/board_io.c`의 `board_touch_read()` 좌표 변환을 수정합니다.

## 5. 외부 USB(J1) 경로 벤치 시험 (약 40분) [기본 + 권장]

1. 배선합니다(`electronics/harness.json`, 그림은 `docs/img/m6_wiring.png`).
   - 4090 JP1-2(VBUS) → MF-R075 → J1-4
   - JP1-1(GND) → J1-6
   - JP1-6(D+) → J1-1
   - JP1-5(D−) → J1-3
   - D+/D−는 1 cm에 한 번꼴로 꼬아 170 mm로 만듭니다.
2. 아직 소켓(B1)이 없으면 J1 헤더 핀에 1.27 mm 점퍼를 쓰거나 임시로 테스트 클립을 씁니다. **헤더 핀에 직접 납땜하지 않습니다.**
3. **보드 자체 USB-C는 뽑습니다. 동시 연결은 금지입니다.**
4. PC → 4090에 연결합니다.
5. **G1-E7 합격 기준**:
   - 장치 관리자에 "USB JTAG/serial debug unit"이 보임
   - `python -m esptool --port COMx read_mac` 10회 연속 성공
   - 플래시 1회 성공
   - 모니터 로그의 VCC ≥ 4.0 V(1 m 케이블)
   - 화면에 "전원 약함"이 뜨지 않음
6. **불합격 시**:
   - 열거가 안 되면 D+/D−가 뒤바뀌었는지 확인합니다.
   - 간헐적으로 실패하면 꼬임을 더 촘촘히 하고 배선을 120 mm로 줄입니다. 이 경우 CAD는 고칠 필요가 없습니다.

## 6. 부저 구동 시험 (약 30분) [기본]

1. 만능기판(24×18 mm)에 조립합니다.
   - SOT-23 변환기판의 G·D·S 핀을 확인한 뒤 AO3400A를 올립니다.
   - IO16 → 100 Ω → G
   - G → 100 kΩ → S/GND
   - D → 부저(−)
   - 부저(+) → +5 V
   - 1N4148: 캐소드가 +5 V 쪽
2. J1-8(IO16)을 연결하고 알람·완료음을 재생합니다.
3. **G1-E8 합격 기준**:
   - 전류계로 본 평균 증가분 ≤ 60 mA
   - 1 m 거리에서 분명히 들림
   - 전원을 10번 다시 넣는 동안 부팅 중 소리 0회
   - MOSFET을 손가락으로 만졌을 때 미지근하지 않음
4. **불합격 시**:
   - 소리가 작으면 펌웨어 음 범위를 2.3–2.5 kHz로 좁힙니다(`board_io.c`의 `k_alarm`).
   - 부팅 중 소리가 나면 100 kΩ 풀다운 납땜을 확인합니다.

## 7. BLE 휴대폰 연결 (약 30분) [기본]

1. Android 앱(V17에 BLE 모듈 통합 빌드)이 필요합니다. 아직 없으면 nRF Connect 같은 범용 BLE 앱으로 서비스가 보이는지, 페어링이 되는지만 확인합니다.
2. **G1-E9 합격 기준**:
   - 볼 화면의 6자리를 폰에 입력해 본딩 성공
   - 파트너 변경과 시간 동기화가 반영됨
   - 본딩하지 않은 다른 폰에서는 쓰기가 거부됨
3. **실제 앱 연동은 아직 UNVERIFIED**입니다. V17 화면 통합과 APK 빌드는 별도 작업입니다.

## 8. 시간 초기화·복구 (약 15분) [기본]

1. 앱으로 시간을 동기화합니다 → 시계가 표시됩니다.
2. 알람을 "현재 + 3분"으로 맞춥니다.
3. **USB를 30초 뽑았다가 다시 꽂습니다.**
4. 합격 기준:
   - 화면에 `--:--`와 "시간 맞춰줘"가 표시됨
   - 3분이 지나도 알람이 울리지 않음
   - 앱 연결 → 자동 동기화 → 시계 표시
   - 이미 지난 알람은 울리지 않고, 다음 날 같은 시각에 울림(시간 동기화 후 시계를 다음 날로 설정해 확인)

## 9. 소비전류·전압 (약 20분) [권장]

외부 포트에 USB 전류계를 연결하고 다음 상태에서 전류를 기록합니다.

| 상태 | 기준 |
|---|---|
| 홈(밝기 40) | 기록 |
| 밝기 100 + 아이보리 화면 | 기록 |
| 알람 울림 | 기록 |
| 화면 OFF | 기록 |
| 모든 상태 | **최대 < 400 mA**(MF-R075의 50 °C 홀드 전류 0.54 A 대비 여유) |

- 30분 연속 동작 뒤 PTC와 보드를 손으로 만졌을 때 뜨겁지 않아야 합니다(멀티미터 온도 프로브가 있으면 < 50 °C).

## 10. G1 판정 → 핏 키트 출력 의뢰

- G1-M1–M4, G1-E1–E2, G1-E4–E8, 8번 항목이 모두 합격이면 G1 통과입니다.
- G1을 통과하면 소켓(B1) SKU를 확정해 주문하고, 핏 키트(C1)를 출력 업체에 의뢰합니다.
  - 보낼 파일:
    - `cad/out/step/bezel_black.step`
    - `cad/out/step/display_plate_petg.step`
    - `cad/out/fitkit/*.step` 5개
  - 함께 보낼 문서: `procurement/RFQ_M6_KO.md`
  - **본 출력을 맡길 업체·재료·설정과 똑같이** 요청합니다.

## 11. G2 핏 키트 검사 (약 1시간) [기본]

`G1_G2_INSPECTION_KO.md`의 G2-K1–K10을 수행합니다.

| 불합격 | 수정 파라미터 (`cad/m6_params.py`) |
|---|---|
| K1–K2 포켓이 빡빡함 | `POCKET_R` +0.1 단위 |
| K4 유리–립 틈 | `LIP_GAP` |
| K7 개구 0.30 게이지가 안 들어감 | `OPENING_R` +0.1 단위(최대 0.75까지. 그 이상이면 버튼 틈이 눈에 띔) |
| K8 USB 플러그 | `USB_SLOT_CLR`, `USB_POCKET` |
| K9 조인트 | `COUNTERBORE_R` |

수정했으면 `tests/run_all.sh`를 다시 통과시키고 **핏 키트만** 재출력합니다.

## 12. 본 출력 → 조립

- G2를 통과하면 본 출력(C2)을 발주합니다.
- 조립 순서는 `README_KO.md` §2를 따릅니다.
- 조립 전에 보드 자체 USB-C에 **먼지마개**를 꽂고, 플레이트에 "외부 포트 사용 중 꽂지 말 것" 라벨을 붙입니다.
