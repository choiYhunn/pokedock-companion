# 휴대폰 없이 시계 맞추기 (펌웨어 m6-0.3.0)

## 왜 필요한가

- M6에는 메인 배터리도 RTC 백업 셀도 없습니다. USB 전원이 끊기면 PCF85063 RTC의 시각이 사라지고, 다시 켜면 `--:--`와 "시간 맞춰줘"가 표시됩니다.
- 지금까지는 Android 앱의 BLE `time_sync`만 시계를 복구할 수 있었습니다. **iPhone Safari 웹앱은 Web Bluetooth가 없어서 볼에 연결하지 못합니다.** iPhone 사용자는 정전 뒤 시계와 알람을 쓸 수 없었습니다.
- 그래서 볼 자체의 터치만으로 날짜·시간과 알람 시각을 맞추는 기능을 먼저 넣었습니다. Wi-Fi는 필요 없습니다.

## 사용법 (선물 받는 사람용 한 줄 안내)

| 하고 싶은 것 | 방법 |
|---|---|
| 시계 맞추기 | 홈의 **"시간 맞춰줘"** 탭(또는 화면을 아래로 끌어 메뉴 → 위쪽 **"시간"**) → 년·월·일·시·분을 **−/+**로 맞추며 **다음** → 마지막 **저장** |
| 알람 시각 바꾸기 | 메뉴의 **"알람"을 길게** → 시·분 → **저장**(알람이 켜짐). 짧게 누르면 켜기/끄기 |
| 취소 | 첫 화면의 **취소**(아무것도 바뀌지 않음). 중간에서는 **이전** |

- −/+를 **길게 누르면** 빠르게 바뀝니다. 각 칸은 자기 범위 안에서만 돌기 때문에 분을 넘겨도 시가 바뀌지 않습니다.
- 편집 중 알람이 울리면 편집은 닫히고 알람 화면이 먼저 나옵니다.
- 시작 날짜는 마지막으로 알던 날짜(휴대폰 동기화나 이전 수동 설정), 그것도 없으면 펌웨어 날짜(2026-10-31)입니다. 보통은 "다음"만 누르고 시·분만 맞추면 됩니다.

## 화면 설계 (36.75 mm 원형 패널)

- 1 px ≈ 0.079 mm라서 한 화면에 한 칸만 편집합니다. −/+는 지름 110 px(8.7 mm) 원 버튼, 이전·다음은 120×64 px입니다.
- −/+ 기호는 글자가 아니라 44×10 px 막대로 그립니다(“-” 글자는 잉크 높이가 몇 px밖에 안 됨).
- 글자는 40 px 이상, 값은 120 px 숫자(년도는 80 px)입니다. 모든 글자와 버튼이 원 안에 들어오는지는 `tests/ui_sim_probe.py`가 시뮬레이터 화면으로 검사합니다(버튼 외곽이 원보다 2 px 이상 안쪽, 최소 변 64 px 이상).

## 구현 위치

| 파일 | 내용 |
|---|---|
| `core/clock_set.hpp` | 날짜 계산(윤년, 월 길이), 현지 ↔ UTC 변환, 칸 단위 −/+, 시작 날짜 제안. 호스트 테스트와 펌웨어가 같은 코드를 씀 |
| `core/pokedock_core.hpp` `Core::wall_clock_set()` | 손으로 맞춘 시계가 "미래의 잘못된 날짜"에 기록된 알람 기록 때문에 며칠 동안 조용해지지 않게 보정. 같은 날 이미 끈 알람은 다시 울리지 않음 |
| `firmware/main/ui.cpp` | 편집 화면(LVGL), 메뉴 "시간" 버튼(이전 "뒤로" 안내 글자 자리, 위로 끌기로 닫기는 그대로), "시간 맞춰줘" 탭 |
| `firmware/main/app_main.cpp` | 저장 → RTC 기록(`set_utc`) → 알람 기록 보정 → NVS 저장 → BLE 상태 알림 |
| `ui/M6_Device_Simulator.html` | 같은 화면·동작의 브라우저 시뮬레이터 |
| `tests/clock_set_test.cpp` | 2026–2099 매일 왕복 변환, 윤년, 칸 순환, 정전 뒤 알람 보정 |

BLE 프로토콜(v2)은 바꾸지 않았습니다. 상태의 `fw` 값만 `m6-0.3.0`으로 올렸습니다.

## Wi-Fi NTP 검토 (구현하지 않음)

| 방법 | 장점 | 문제 | 판단 |
|---|---|---|---|
| A. 기기 터치 설정 (구현) | Wi-Fi·앱·인터넷 불필요. 어떤 휴대폰과도 무관 | 사람이 정확히 입력해야 함(±1분) | **기본 방법** |
| B. 집 Wi-Fi + SNTP 자동 동기화 | 정전 뒤 자동 복구, 초 단위 정확 | 원형 소형 화면에서 SSID·비밀번호 입력이 사실상 불가 → 별도 프로비저닝 필요. 공유기 변경 때마다 재설정. 비밀번호를 NVS에 평문 저장. BLE와 2.4 GHz 공존 시 소비전류·메모리 증가 | 보류 |
| C. 볼이 임시 AP를 열고 휴대폰 브라우저가 접속해 휴대폰 시각을 보내는 방식(SoftAP + 웹페이지) | iPhone Safari에서도 동작. 인터넷·비밀번호 불필요 | 별도 웹서버·AP 보안(접속 제한, 시간 제한)과 사용자 안내가 필요. 펌웨어 크기와 시험 범위 증가 | 다음 후보 |
| D. RTC 백업 셀 추가 | 정전 시 시계 유지 | J2가 3V3에서 전류 제한 없이 충전됨(Rev C에서 제외한 이유). 회로 변경 필요 | 하드웨어 리비전 사항 |

결론: 이번 외주 제작에는 A만 넣습니다. B·C는 실물 G1 이후 사용성 문제가 남으면 별도 리비전으로 검토합니다. 어떤 경우에도 **Wi-Fi 없이 시계를 설정할 수 있어야 한다**는 조건은 A로 이미 충족됩니다.

- 호스트: `tests/clock_set_test.cpp` 통과, 기존 타이머·알람 회귀(`core_regression_test.cpp`), 프로토콜, BLE E2E 그대로 통과.
- 시뮬레이터: 정전 화면 → "시간 맞춰줘" 탭 → 2026-11-02 07:58 설정 → 시계 표시, 알람 08:00을 기기에서 설정 → 정확한 분에 울림, 취소 시 변경 없음, 편집이 집중 타이머를 시작하지 않음.
- ESP-IDF v5.3.2 타깃 빌드 통과.
- **실물 미검증**: 실제 터치 감도와 −/+ 버튼 크기 체감, RTC 기록 후 재부팅 유지(G1-E10에서 확인).
