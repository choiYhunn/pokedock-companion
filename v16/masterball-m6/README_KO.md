| 부품 | 재료 | 핵심 변경 |
|---|---|---|
| 버튼 베젤(검정) | PETG | 유리 Ø46 포켓(+0.30), 앞 립 1.5 mm, 창 Ø37.6. **유리 앞면이 베젤 면에서 2.1 mm 뒤**(M4는 8 mm 함몰 아니면 간섭이었음). 뒷면 M2 인서트 4개 |
| 디스플레이 플레이트 | PETG | 보드 **자체 M2 스탠드오프 4개**에 접시머리 M2×6으로 고정 → 유리에는 하중 0. J1/J3 소켓 창, BOOT/RESET 핀홀 |
| 하단 쉘(아이보리) | PLA | **45° 원뿔 받침**(바닥 Ø73)으로 외관 서포트 없이 출력하면서 굴러가지 않게 함. 스피곳, M3 기둥 3개, 하부 백스톱 리브(플레이트를 M2×10 2개로 클램프), USB-C 포트 블록, 부저 포켓, 강재 웨이트 포켓 |
| 상단 쉘(퍼플) | PLA | 스피곳 카운터보어, M3 인서트 보스 3개, 상부 백스톱 리브(0.4 mm 간극 + 폼), 귀 장식 평면 시트(핀 2개 + 안쪽에서 M2), M 인레이 포켓 |
| 벨트(검정) | PLA | C자 링(버튼 자리 개방), 스피곳에 0.35 mm 간극으로 끼움 |
| 귀 장식 ×2 | PLA 핑크 | 평면 바닥 + Ø3 핀 2개, 교체 가능 |
| M 인레이 | PLA 화이트 | 위쪽 면이 구면을 따름, 접착 |

**USB-C 접근 문제 해결**: 공식 형상 분석 결과, 보드 USB-C는 화면 평면의 옆 방향을 향하므로 138 mm 구체의 앞 극 근처에서는 어떤 플러그를 꽂아도 공 표면 밖으로 튀어나옵니다. 그래서 보드 USB-C는 정비용으로만 남기고, **J1 헤더의 USB_5V·GND·D+·D−를 하단 후면 외부 USB-C 포트로** 연결했습니다.

### 조립 순서

1. 하단 쉘에 USB-C 브레이크아웃을 안에서 밀어 넣고 M2.5×8 ×2로 고정합니다. 부저를 포켓에 넣고(핫멜트 소량), 웨이트(선택)를 넣습니다.
2. 보드를 베젤 포켓에 뒤에서 넣고(0.5 mm 폼 링 선택), 플레이트를 대고 M2×6 ×4(스탠드오프) + M2×6 ×2(베젤 상단 인서트)로 고정합니다. J1 소켓을 꽂습니다.
3. 디스플레이 서브어셈블리를 하단 쉘에 수직으로 내려 넣고, 하부 리브 뒤에서 M2×10 ×2로 베젤 하단 인서트에 체결합니다.
4. 배선을 정리합니다(케이블 타이). 벨트를 스피곳 위로 내려 끼웁니다.
5. 귀 장식과 M을 미리 단 상단 쉘을 수직으로 내려 덮습니다.
6. 바닥에서 M3×50 ×3을 조이고, 실리콘 발 6개를 붙입니다.

분해는 역순입니다. 바닥 나사 3개만 풀면 상단 쉘이 열립니다.

이번 단계에서 검사가 잡아낸 **내 설계 오류**도 기록합니다(모두 수정 후 재검증).
1. 보드 좌표 매핑이 거울상(det −1)이었습니다 → 회전으로 수정했고, BOOT/RESET 위치가 −x 쪽으로 바뀌었습니다.
2. 상단 보스 3개가 원점에 생성되었습니다(위치 인자 누락) → 체결 검사 항목을 신설해 재발을 방지했습니다.
3. USB 보드 고정 나사에 드라이버가 닿지 않는 방향이었습니다 → 블록을 PCB 아래로 뒤집었습니다.
4. 플레이트 가장자리 재료가 부족했습니다(88 %) → 반경을 29.0 mm로 키웠습니다.
5. 하단 쉘 외관에 서포트가 필요했습니다 → 45° 원뿔 받침을 추가했습니다.
6. 베젤 스커트에 서포트가 필요했습니다 → 뒷면이 베드에 닿도록 출력 방향을 바꿨습니다.

## 4. 전기 (`electronics/`)

- `harness.json`: 배선 표. 출발·도착 핀을 공식 회로도(J1/J2/J3)와 펌웨어 핀 정의에 자동으로 대조합니다(`tests/harness_check.py` PASS).

- 부저(Rev C): IO16(J1-8, 스트래핑 핀 아님) → 100 Ω → AO3400A 게이트, 게이트–소스 100 kΩ 풀다운(부팅 중 무음), 드레인 → Soberton WT-1205(−), WT-1205(+) → USB 5 V, 1N4148 플라이백(캐소드 +5 V). Rev A의 680 Ω + 2N3904 방식은 포화가 보증되지 않아 교체했습니다(`docs/REV_C_FINAL_KO.md`). LEDC PWM으로 멜로디를 내고, 소리 ON/OFF를 지원합니다.
- 보드 내부 사실(회로도 근거): BAT_ADC(GPIO4)는 VBAT가 아니라 **VCC**를 측정합니다. 따라서 USB 전압 저하 경고에 사용합니다.
- 금지 사항: 마이크로SD 카드 삽입(카드 모서리가 베젤 포켓과 간섭). 자산은 플래시에 저장하므로 SD가 필요 없습니다.

## 6. 타이머·알람 (`core/pokedock_core.hpp`)

감사에서 찾은 결함 6건을 모두 수정했습니다.
- 재부팅이나 시간 동기화 점프가 있어도 10분 이내면 알람을 울립니다.
- 23:59 알람이 자정을 넘는 폴링 간격에서도 울립니다.
- 스누즈는 단조 시계로 판정합니다.
- 2분 동안 울리면 자동 스누즈, 3회 뒤 자동 종료합니다.
- 실행 중 재시작을 거부합니다.
- `last_fired_day`를 NVS에 저장합니다.

**회귀 테스트 44/44 PASS**: 감사 프로브 9개, 400일 실시간 1초 시뮬레이션(정확히 400회 울림, 모두 07:30), 무작위 시계 점프·재부팅 퍼징 300회(1,615회 울림, 위반 0).

## 7. BLE (`core/protocol.hpp`, `mobile/`)

- 상태는 114 B로 MTU 185 안에 들어갑니다.
- 기기 단위 테스트 33/33 PASS.
- **E2E 12/12 PASS**: 실제 C++ 엔진 ↔ 실제 JS 클라이언트, 링크 시뮬레이션.

  - 미인증 쓰기 거부
